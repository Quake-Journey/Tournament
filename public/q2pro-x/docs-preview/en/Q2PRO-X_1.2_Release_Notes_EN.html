Q2PRO-X 1.2: release notes

Q2PRO-X 1.2 is the public release after the 1.0 line and the 1.1 /

1.1A beta branch. The point of this version is not a single isolated feature.

It turns the client into a more complete modern Quake II tool for playing,

watching demos, tuning visuals, sound, networking, and UI behavior.

Who this release is for

  1. Players who want a modern q2pro-compatible client without assembling a

long chain of patches manually.

  1. Duel and TDM players who care about prediction, visibility, latency

control, readable HUDs, and a fast server browser.

  1. Demo watchers: MVD/DM2 playback now has its own browser/player layer,

analytics, viewing modes, and a unified demo-visual profile.

  1. Users importing older r1q2 / q2pro configs who do not want to repair

mouse behavior, zoom, menu defaults, and cvars by hand.

Major changes from 1.0 to 1.2

Guided Menu and safe first run

In 1.2 the modern guided menu is the main entry point. The legacy menu still

exists, but a new user should immediately see a coherent structure:

  • Quick Setup;
  • Video / Sound / Controls;
  • Online Play Setup;
  • Demo Browser / Demo Player;
  • Cvar Browser;
  • Q2PRO-X engine-room pages.

When upgrading an old config from 1.0 / 1.1 / 1.1A, the engine runs a narrow

schema migration. If cl_q2prox_cfg_version is missing or older than 1.2, it

applies only safe recommended UI defaults, such as the modern guided menu and

Q2PRO-X config autosave. It does not wipe the full user profile.

Video and visuals

The default Windows video backend is now win32egl when the build contains

EGL / ANGLE. This backend is friendlier to video capture: NVIDIA ShadowPlay

and OBS game capture avoid the WGL fullscreen artifacts that motivated this

branch. win32wgl remains available as a fallback.

The video menu exposes practical controls:

  • video backend: win32egl / win32wgl;
  • resolution: desktop or a concrete WxH;
  • windowed mode;
  • fullscreen type: desktop / exclusive;
  • refresh rate;
  • fullscreen fit: fill / aspect;
  • render scale and filter;
  • OLED protection;
  • post-processing, bloom, brightness, dynamic lights.

Visibility Highlights

Highlights are now a dedicated visual system:

  • items: shell, tint, shell+tint, alpha, brightness, scale;
  • weapons: separate toggles and colors;
  • players: all / random FFA / duel / auto / team / model;
  • team colors for live TDM/duel;
  • model color overrides for demo watching and other cases where friendly vs

enemy truth is not reliable.

These settings are mod-local. During .dm2 / .mvd2 playback they are saved

to baseq2/q2pro-x/demo_visual/q2pro-x.demo.cfg, so demos from different mods

can keep one consistent visual profile.

Demo Browser and Demo Player

1.2 makes demos a product area of their own:

  • modern overlay browser with an index, tabs, search, details, favorites, and

playlist flow;

  • modern demo player overlay with timeline, pause/seek, speed/actions,

autohide, volume override, gun/skin override;

  • MVD-only director mode: next frag / quad / penta / leader;
  • analytics: traffic / frags / pickups / all, HUD overview, world mode, trail

mode;

  • trail height mode: origin / feet, hover Z, outline;
  • MVD2 item timers: ghost models, countdown labels, item strip, per-item

toggles, and color editor.

Voice Chat

Built-in voice chat is a separate side-channel, not a replacement for game

say / say_team.

Main model:

  • vc_enable - master switch;
  • vc_autojoin - enter a voice room when joining a game server;
  • vc_room_mode server - room is derived from the current game server;
  • vc_server defaults to the hosted control-plane

https://voice-api.q2pro-x.com;

  • microphone selection is available from the menu and through

voice_mic_list / voice_mic_pick;

  • transmit mode can be push-to-talk or VAD.

The current phase requires OpenAL for both transmit and receive.

Network play

Network play received several user-facing layers:

  • modern server browser with filters, sorting, detail pane, row colors,

fullscreen/compact mode, and persistent settings;

  • OpenTDM Team HUD with passive teammate-state and LAST MSG;
  • laghax HUD and network feel smoothing modes;
  • adaptive ping gate for weapon predict and player predict;
  • fine-grained weapon FX visibility toggles;
  • client UDP port autoprobe: RTT mode and XQ3A mode.

Controls, mouse, and zoom

For old config migration, cl_mouse_behavior_mode provides:

  • q2pro - native Q2PRO-X behavior;
  • r1q2 - compatibility mode for older configs.

Zoom has clear dedicated settings:

  • FOV;
  • sensitivity mode: auto / manual;
  • manual sensitivity;
  • zoom time;
  • walk while zoomed;
  • separate zoom crosshair.

Cvar Browser

The built-in cvar reference is now more than a list:

  • category tabs;
  • favorites;
  • commands tab;
  • RU/EN search input;
  • copy, selection, Ctrl+A, clear;
  • live value column;
  • detail pane with descriptions and accepted values;
  • fullscreen, scale, opacity, remember last tab;
  • execute commands from the browser and return after the console.

It is the main in-client place to understand what a variable does without

leaving the game.

Upgrading from 1.0 / 1.1 / 1.1A

  1. Back up your old folder if it contains important demos, paks, cfg files,

screenshots, or local mods.

  1. Extract 1.2 as a clean runtime package. The release does not ship user

q2pro-x.cfg files.

  1. If you import an old baseq2/q2pro-x/q2pro-x.cfg, the first 1.2 start

runs a narrow migration and adds cl_q2prox_cfg_version "1.2".

  1. Check Options -> Controls / Mouse and Options -> Video after the first

start, especially if your old config came from r1q2.

  1. For demos, check Options -> Demo Player and `Options -> Visibility

Highlights`: the demo-visual profile is now separate from mod-local

profiles.

What did not change

  • Base Quake II content compatibility is preserved.
  • Older console commands and legacy menu paths still exist.
  • Mod cfg and user cfg files should not be forcibly erased.
  • Visual and demo-only features should not become live-play cheats: demo

analytics and item timers use recorded demo data, not hidden live-server

information.

Practical first-run advice

After the first start, open:

  • Options -> Quick Setup;
  • Options -> Video;
  • Options -> Controls / Mouse;
  • Options -> Sound & Acoustics;
  • Options -> Online Play Setup;
  • Options -> Demo Player.

That is enough to bring 1.2 into a clean working state without manually

editing cfg files.
